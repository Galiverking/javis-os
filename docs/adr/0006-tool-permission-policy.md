# ADR-0006: Tool permission policy อยู่ในโค้ด ไม่ใช่ใน prompt

- สถานะ: Accepted
- วันที่: 2026-11-13

## Context

LLM อาจถูกโน้มน้าว (prompt injection) หรือเข้าใจผิดให้เรียก tool อันตราย
การพึ่ง prompt อย่างเดียว ("ห้ามลบไฟล์") ไม่ใช่การป้องกันที่เชื่อถือได้

## Decision

ทุก tool มี `permission` เป็น metadata ที่ประกาศในโค้ด:
`SAFE` / `CONFIRM` / `DANGEROUS`
Policy engine ตรวจก่อนรันทุกครั้ง โดยไม่สนใจข้อความจาก LLM
- `SAFE` → รันทันที
- `CONFIRM` → orchestrator ถามผู้ใช้ด้วยเสียง, timeout 8 s = ปฏิเสธ
- `DANGEROUS` → ปิดใน config โดย default; ต้องเปิดและยืนยันทุกครั้ง

เพิ่มกฎ: `shell.run` รับ argv list เท่านั้น, จำกัด cwd, blocklist,
และเนื้อหาจากเว็บถูกครอบ `<untrusted>` ห้ามตีความเป็นคำสั่ง

## Consequences

ข้อดี
- ความปลอดภัยไม่ขึ้นกับคุณภาพของ LLM
- audit ตรวจย้อนได้ว่าใครอนุมัติ action ไหน
- เพิ่ม tool ใหม่ได้โดยประกาศระดับความเสี่ยงชัดเจน

ข้อเสีย
- คำสั่งที่ควรเร็วอาจต้องยืนยันเพิ่ม (เช่น ปิดแอป)
- ต้องออกแบบ UX การยืนยันทางเสียงให้ไม่น่ารำคาญ
- ผู้ใช้อาจกดยืนยันอัตโนมัติจนเคยชิน → ต้องแสดงผลกระทบให้ชัด

## Alternatives

- allowlist ใน prompt: เปราะและตรวจสอบไม่ได้
- YOLO mode: เร็วแต่เสี่ยงเกินไปสำหรับเครื่องที่มีข้อมูลส่วนตัว
- sandbox ระดับ OS (container): เหมาะกับ tool บางประเภท แต่หนักเกินไปสำหรับ MVP

## หมายเหตุ

ทุก action ต้องมี audit record แม้ถูกปฏิเสธ (`status = denied`)

## ข้อโต้แย้ง / แย้งแผน (Critique)

1. **Voice-Only Confirmation ไม่ปลอดภัยพอสำหรับระดับ CONFIRM:** การยืนยันด้วยเสียง เช่น "ใช่ / ยืนยัน" มีความเสี่ยงต่อ STT Mishearing (เช่น พูดว่า "ไม่ใช่" แต่ตัดเสียงคำว่า "ไม่" หายไป หรือเสียงคนรอบข้าง/ทีวีดังแทรก)
2. **ไม่มี GUI Visual Feedback:** เมื่อผู้ใช้สั่งงานบนเครื่องเดสก์ท็อป การที่ระบบถามลอยๆ ทางเสียงแล้วรอฟัง 8 วินาที สร้าง Cognitive Load สูง และผู้ใช้ไม่เห็นผลลัพธ์ที่ชัดเจนว่าคำสั่งที่กำลังจะรันคืออะไรกันแน่ (เช่น ปิดแอปไหน หรือรัน argv อะไร)
3. **ข้อเสนอแนะ:** คำสั่งระดับ `CONFIRM` ควรแสดง **Desktop Notification หรือ GUI Dialog Modal (`zenity` / Cinnamon Notification Action)** ที่หน้าจอควบคู่เสมอ เพื่อให้ผู้ใช้สามารถคลิกกดอนุมัติ/ยกเลิกได้ทันทีโดยไม่ต้องตะโกนตอบ

✅ **มติการปรับปรุง (ADR-0006 Resolution v0.2):**
- ยกเลิกการยืนยันคำสั่งระดับ `CONFIRM` / `DANGEROUS` ด้วยเสียงเพียงอย่างเดียว
- เปลี่ยนเป็น **Hybrid Confirmation Policy (Voice + Desktop GUI Modal):**
  1. ส่งเสียงเตือนสั้นๆ ทางลำโพง
  2. เด้งหน้าต่าง GUI Dialog ผ่าน `zenity --question` หรือ Cinnamon Notification Action บนหน้าจอ แสดงคำสั่งที่จะรันอย่างโปร่งใส และให้ผู้ใช้กดปุ่มยืนยันหรือยกเลิกได้ทันที
- ขจัดปัญหา STT Mishearing และเพิ่มความปลอดภัยสูงสุดให้กับระบบ
